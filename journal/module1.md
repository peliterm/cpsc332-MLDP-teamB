## Initial project direction

Our initial direction is a small, beginner-friendly language focused on clear input-validation rules and understandable error messages. Initial examples could distinguish a missing input from a valid zero and handle out-of-range values consistently. We will refine the scope and evaluation criteria in Module 2.

## Starting evaluation criteria

Based on the Module 1 reading and discussion, we will use these checks to evaluate our language feature:

1. **Readability and writability:** A teammate who knows the basic syntax can explain a short example and use the feature on a representative task.
2. **Reliability:** Expected behavior is defined for valid inputs, invalid types, and boundary cases.
3. **Consistency:** The feature fits the rest of the language without surprising special cases.
4. **Performance and cost:** Any safety checks are worth their overhead, and the design stays feasible within our project scope.

We will refine these checks into the Module 2 criteria analysis.
