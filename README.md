## Project Description

Our initial direction is a small, beginner-friendly language focused on clear input-validation rules and understandable error messages. We will explore how a feature can distinguish missing inputs from valid values, check allowed ranges, and explain validation failures. We will refine the scope and evaluation criteria in Module 2.

Over the term, we will develop evaluation criteria, syntax and grammar, semantics, data types, control flow, memory, and concurrency considerations. This repository will hold our weekly design journal and supporting artifacts for the final document and presentation in Module 8.

## Team Charter

**Roles**
- Michael Pelitera and Wyatt Rose serve as co-leaders, sharing responsibility for planning, coordination, and reviewing work.
- Both members contribute to every deliverable and agree on how to divide tasks.
- One member submits each deliverable on behalf of the team. We will agree on the submitter for each module and rotate that responsibility.

**Communication**
- Primary channel: our Canvas group discussion, so the instructor can see our collaboration.
- Task tracking: GitHub issues, one issue per piece of work.
- We aim to respond to each other within 24 hours and flag any availability limits early.

**Weekly schedule**
- The Canvas deadline for each assignment controls the submission date and time.
- Starting in Module 2, we propose having each member's draft ready by Friday at 11:59 pm Eastern, reviewing on Saturday, and submitting by the Canvas deadline.

**Workflow**
- After the repository's initial README and license are created, substantive changes use a branch and pull request.
- We normally ask the other member to review before merging. If a deadline arrives without a response, the active member may merge the available work, record that peer review is pending, and leave follow-up items for the team. A self-merge does not count as teammate approval.
- Commit messages say what changed and why, for example "Add BNF rules for if and while statements."
- Each journal entry lives in `journal/moduleN.md`.

**Ground rules**
- Each of us owns the files we author. We suggest changes to each other's work through pull request comments instead of rewriting it.
- If one of us cannot meet an agreed deadline, we say so in the group discussion as early as possible and agree on any work that needs to be reassigned.

**Resolving disagreements**
- We discuss it in the related issue or pull request and lay out the trade-offs.
- We aim for agreement before the internal review deadline. If a decision is needed to meet the submission deadline, the member submitting that deliverable records the available input and reasoning for a provisional decision, which the team can revisit.
- Ongoing participation problems go to the instructor.
